## Phase 1 — MVP ✅ 완료

```
├─ 지원 현황 CRUD
│  회사명, 직군, 지원 날짜, 마감일, 공고 URL, 메모 등록
├─ 전형 단계별 히스토리 관리
│  서류 → 코테 → 1차 → 2차 → 최종 단계별 결과 기록
├─ 대시보드
│  전체 현황 카운트, 이번 주 면접 일정, 마감 임박 공고(D-3 이내)
├─ 캘린더
│  면접 일정·서류 마감일 시각화 (FullCalendar)
├─ 카카오 소셜 로그인
├─ 프로필 이미지 변경 (AWS S3 연동)
├─ 카카오 나에게 보내기 알림
│  ├─ 알림 타입: D-7, D-3, D-1, D-Day 고정 발송
│  ├─ 발송 시각: 매일 오전 9시 고정 (KST)
│  ├─ 지원건별 알림 ON/OFF 가능
│  │  예) 네이버 알림 OFF → 네이버 관련 알림 전부 안 감
│  │      카카오 알림 ON  → 카카오는 정상 발송
│  │  기본값: ON
│  └─ 마이페이지에서 알림 발송 이력 조회 및 선택 삭제
├─ Docker (로컬 개발 환경)
│  ├─ 백엔드 Dockerfile
│  ├─ 프론트엔드 Dockerfile
│  └─ docker-compose.yml
├─ 보안 강화
│  └─ Swagger 운영 환경 비활성화 (spring.profiles 분리)
└─ 운영 배포 ✅
   ├─ AWS EC2 (Amazon Linux, t3.micro) — 프론트/백엔드/MySQL 올인원
   ├─ Nginx — 리버스 프록시 + HTTPS (Let's Encrypt, jscope.duckdns.org)
   ├─ Docker Hub — 이미지 레지스트리 (2000jch/jobscope-*)
   └─ GitHub Actions — CD 자동화 (main 머지 시 EC2 자동 배포)
```

## Phase 2 — 인사이트 ✅ 완료

### 설계 원칙
- 추가 데이터 입력 없음 — Phase 1에서 입력된 히스토리 구조만으로 분석
- 분석과 넛지 동시 출시 — 빈 분석 화면 자체가 데이터 입력 동기 부여
- 분석 화면에 신뢰 지표 필수 — 숫자만 던지지 않고 "N건 중 M건 기준" 맥락 제공

### 넛지 채널 구분
- 대시보드: "히스토리 미입력 지원건 N건" — 행동 유도, 클릭 시 해당 지원건으로 이동
- 분석 화면: 신뢰 지표 + "오래된 진행중 상태 N건" — 맥락 제공
- 카카오 알림: 기존 역할 유지 (면접/마감 리마인더), 넛지 추가 없음

### 기준 데이터 정의
- 통과율 계산: 해당 단계의 결과(합격/불합격)가 확정된 지원건만 분모에 포함 (Stat 기준)
- 진행중(결과 대기) 건수는 단계 사이에 주석으로 표시 — 퍼널 연속성 설명용
- 히스토리가 아예 없는 지원건은 분석에서 완전 제외

### MY 탭 — 취준 여정 뷰 (개인용)

```
├─ 헤더
│  ├─ 프로필 + 이름 + 취준 기간 (첫 지원일 ~ 현재 또는 최종 합격일)
│  └─ 현재 상태 배지 (진행중 / 최종 합격)
├─ 요약 카드 (동적 구성 — 사용자 히스토리 기반)
│  ├─ 공통: 총 지원 건수, 최종 결과
│  └─ 사용자 전형 구조에서 특징적인 단계 자동 선택
│     예) 코테 많이 본 사람 → 코테 통과율 / 면접 위주 → 면접 진출 수
├─ 단계별 퍼널 (Phase 2 분석 화면과 동일 엔진)
│  사용자가 실제 경험한 단계만 표시, 가장 큰 드롭 구간 강조
└─ 월별 타임라인 차트
   월별 지원 / 면접 / 합불 이벤트 시각화
```

Phase 3에서 추가: 합격자 코멘트 입력 + 고유 URL 공유 버튼

### 분석 화면 구조

```
├─ 상단 — 신뢰 지표 (한 줄)
│  "분석 대상 10건 · 히스토리 미입력 1건 · 진행중(결과 대기) 2건"
│  미입력/진행중은 클릭 시 해당 지원건으로 이동
│
├─ 중단 — 단계별 통과율 (메인 인사이트)
│  ├─ 퍼널 차트: 서류 → 1차 → 2차 → 최종 (기본 전체 합산 뷰)
│  │  각 단계 통과율 % 표시 (결과 확정 건수 기준)
│  │  드롭이 가장 큰 구간 강조
│  │  단계 사이: "진행중 N건 제외" 주석으로 모수 변동 설명
│  │
│  │  예)  서류  통과율 71%  (5/7건)
│  │           ↓ 진행중 2건 제외
│  │       1차   통과율 67%  (2/3건)
│  │
│  └─ 필터 토글
│     └─ 직군 필터: 직군별 퍼널 분리 조회
│        Phase 3 재검토 조건인 "직군별 데이터 패턴 확인"의 데이터 축적 역할
│        ※ 코테 필터는 제거 결정 (2026-04-21) — 개발자 전용 서비스가 아닌 모든 직군 대상
│
└─ 하단 — 구간별 소요 기간 (참고 정보)
   단계 간 평균 소요일을 타임라인 또는 가로 바 차트로
   예) 서류→1차 평균 14일 / 1차→2차 평균 7일
   전체 평균은 표시하지 않음 (회사마다 전형 구조가 달라 의미 없음)
   결과 확정 건수 기준으로만 계산
```

## Phase 3 — 취준 타임라인 리포트 (Phase 2 완료 + 유저 확보 후)

합격 확정 시 취준 여정을 리포트로 생성·공유. 합격자의 자발적 공유가
바이럴 루프를 만들고, 누적된 리포트가 Phase 4 데이터 기반이 됨.

```
├─ 리포트 구성 (Phase 1+2 기존 데이터로 자동 생성)
│  ├─ 취준 기간 (첫 지원 ~ 최종 합격)
│  ├─ 총 지원 건수 + 단계별 통과율 퍼널
│  ├─ 가장 큰 드롭 구간 + 사용자 선택적 코멘트
│  ├─ 구간별 평균 소요 기간
│  └─ 타임라인 차트 (월별 지원/면접/합불 이벤트)
│
├─ 공유 구조
│  ├─ 최종 합격 기록 시 "내 취준 리포트 만들기" 버튼 활성화
│  ├─ 공개 항목 선택 (회사명 공개/비공개, 단계별 상세/요약 등)
│  ├─ 고유 URL 생성 → SNS/블로그/커뮤니티 공유
│  └─ 리포트 열람 시 "나도 JobScope로 관리해보기" CTA → 가입 유도
│
└─ 바이럴 루프
   합격자 공유 → 블라인드/오카방/취준 커뮤니티 확산
   → 새 유저 유입 → 그 유저가 합격하면 또 공유

[포지셔닝 원칙]
합격자 데이터만 쌓이는 것은 트레이드오프가 아니라 차별점.
"탈락 패턴 분석"이 아닌 "합격자 전형 여정 특화"로 포지셔닝.
링커리어(합격 자소서), 잡플래닛(합격 면접 후기)과 같은 맥락이되,
단계별 소요 기간 + 통과율 + 타임라인이 구조화된 데이터로 차별화.
```

## Phase 4 — 합격자 여정 아카이브 (Phase 3 리포트 누적 후)

Phase 3에서 공유 동의한 리포트가 쌓이면, "합격자들의 전형 여정 모음"으로
자연스럽게 전환. 회사별 익명 집계가 아닌 합격 경로 특화 데이터로 포지셔닝.

```
├─ 합격자 여정 탐색
│  예) 네이버 합격자 3명
│      ├─ 평균 전형 기간: 42일
│      ├─ 코테→1차 평균 소요: 2주
│      └─ 공통 전형 구조: 서류→코테→1차→최종
│  → "이 회사에 붙은 사람들이 어떻게 했는지" 에 특화
│  → 잡플래닛 합격 후기 대비 구조화된 데이터가 차별점
│
└─ B2B (부트캠프·취업학원)
   수강생 전체 취업 현황 및 합격 여정 통계 관리
   재검토 조건: Phase 3 리포트 누적 + 충분한 활성 유저 확보
```
